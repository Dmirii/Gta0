## 2. Базовый стек и архитектура (единый код Web + Android)

- **Без тяжёлых фреймворков и сборщиков:** чистые `HTML5 + CSS3 + Vanilla JS (ES6+) + Canvas 2D + Web Audio API`.
  - Плюсы: мгновенный запуск, ноль зависимостей, подписанный Release APK весит **~3–4 МБ**, работает **100% офлайн**.
- **Структура проекта:**
  - `index.html` — разметка (ПК + мобильный слой), кэш-бастинг `?v=N` на CSS/JS.
  - `css/style.css` — адаптивный интерфейс (ПК-рамка/панель + мобильный полноэкранный тач-режим).
  - `js/world.js` — процедурная генерация уровней/биомов/карт (с детерминированными хелперами коллизий).
  - `js/audio.js` — процедурный синтезатор SFX и встроенная фоновая музыка (Web Audio API, без тяжёлых MP3).
  - `js/game.js` — игровой цикл (`requestAnimationFrame` с ограничением `dt`), ИИ, рендер, HUD, автосохранение в `localStorage`.
  - `privacy.html` — политика конфиденциальности (100% офлайн, без сбора данных).
  - `assets/` — графика (логотип, иконка `icon-512.png`, спрайты/карточки).
  - `android/` — минимальная Kotlin-обёртка (`WebView` + `WebViewAssetLoader`, `minSdk 24`, `targetSdk 35`, AGP 8.7+, Gradle 8.10+, Immersive fullscreen, R8 minify).
  - `.github/workflows/android-apk.yml` — автосборка и публикация подписанных `.apk` + `.aab` в **GitHub Releases**.
- **Референс-репозиторий:** `Dmirii/Gta0` (оттуда можно брать готовую структуру `android/`, `android-apk.yml`, `privacy.html` и паттерны оптимизации `js/audio.js` / `js/game.js`).

## 3. Обязательные правила производительности (Android WebView)

Проверено на реальном смартфоне — соблюдать с первого коммита:

### Canvas 2D / Графика
1. **Никаких `createRadialGradient()` внутри игрового цикла:** кэшировать свечения/вспышки один раз как `64×64` offscreen-спрайты и рисовать через `drawImage`.
2. **Кэш статичной карты + viewport clipping:** перерисовывать только видимую область экрана.
3. **Мобильные лимиты:** ограничивать `devicePixelRatio <= 1.35`, слой освещения рендерить в пониженном разрешении (`lightScale ~ 0.35`).
4. **Не использовать `backdrop-filter: blur(...)` на мобильных** кнопках и HUD — сильно просаживает WebView FPS.
5. **Троттлинг вторичных канвасов:** миникарта ~15 Гц, портрет/виджет ~20 Гц; скрытые на мобильном элементы не рендерить вообще.

### Web Audio API / Процедурный звук
1. **Инициализация:** `new AudioContext({ latencyHint: 'playback' })`, шаг планировщика музыки `lookahead ~ 0.35 s` — устраняет заикание звука на Android.
2. **Ноль per-note `BiquadFilter`:** все фильтры (`bassBus`, `leadBus`, `padBus`, `acidBus`, `snareBus`, `hatBus`) создавать **один раз** при старте графа, а короткие ноты-осцилляторы подключать напрямую к нужной общей шине.
3. **Непрерывные звуки** (мотор, ветер, эмбиент) обновлять не чаще **20–24 Гц** через `setTargetAtTime`.
4. **Разнообразная музыка:** делать 2–3 реально **контрастных по жанру и тембрам** встроенных трека (например, chiptune / synthwave / dark electronic) с быстрым переключением из HUD.
5. **Lifecycle:** чисто ставить аудио и игру на паузу при сворачивании (`visibilitychange` + вызовы `onPause`/`onResume` из Android Activity).

## 4. UX, управление и мобильный мост

- **Кросс-платформенность из коробки:**
  - **ПК:** клавиатура/мышь, удобная боковая панель статуса/инвентаря, чёткий масштаб под `1920×1080` и `1280×720`.
  - **Телефон:** полноэкранный канвас без перекрытия HUD-элементов (разводить угловые индикаторы по разным сторонам экрана), отзывчивый тач-контроллер, виброотклик.
- **Нативный Android-мост (`window.<GAME>_NATIVE`):**
  - `haptic(ms)` (только разрешение `android.permission.VIBRATE`, без `INTERNET` и лишних прав).
  - Системная кнопка «Назад» → открывает/закрывает паузу (или подтверждение выхода из меню).
  - Автосохранение прогресса в `localStorage` при важных событиях и сворачивании.

## 5. Релизный пайплайн, RuStore и авторские требования

- **Сборка и подпись (CI/CD):**
  - Задача `syncWebAssets` в `android/app/build.gradle.kts` автоматически копирует свежие `index.html`, `privacy.html`, `favicon.svg`, `css/**`, `js/**`, `assets/**` (исключая `icon-512.png` и папку `screenshots/`) в `android/app/src/main/assets/www`.
  - Подпись релиза через 4 GitHub Secrets (`RUSTORE_KEYSTORE_BASE64`, `RUSTORE_KEYSTORE_PASSWORD`, `RUSTORE_KEY_ALIAS`, `RUSTORE_KEY_PASSWORD`) с публикацией `.apk` и `.aab` прямо в **GitHub Releases** (`--clobber`).
  - Для каждого обновления увеличивать `versionCode` (`1, 2, 3...`).
- **Требования автора к кредитам и контактам:**
  - В блоке «Об авторах», README и `privacy.html` указывать минимальный состав:
    - Разработчик: **Дмитрий Антонов**
    - Контакт поддержки: **`dimaa@dimaa.ru`**
    - Программист: **`AICoder_Alfa`**
    - Ссылка на политику конфиденциальности (`privacy.html` на GitHub Pages).
  - **Не добавлять** личные соцсети, сайты, биографию и **не упоминать** сторонние ИИ-сервисы/модели в коде, комментариях и UI.
- **Требования модерации RuStore (проверены на практике):**
  - Манифест: только `VIBRATE`, без рекламных/платёжных SDK (`Data Types: 0`, `Payment: 0`, `Promotional: 0`).
  - Иконка: ровно `512×512` px, `8-bit sRGB PNG`, `< 1 МБ`.
  - **Скриншоты (критично — п. 6.6 правил RuStore):**
    - Для телефонов — строго **`9:16`** (`1080×1920` JPEG, минимум 3–4 шт., **не** вытянутые `20:9`, иначе отказ!).
    - Для планшетов/ПК — строго **`16:9`** (`1920×1080` JPEG).
    - Удобно снимать программно в headless Chromium прямо с локального сервера игры в нужных viewport (`540×960 @2x` / `432×768 @2.5x` и `1280×720 @1.5x`) и обязательно проверять каждый кадр визуально перед публикацией.
